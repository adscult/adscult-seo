## Inventory and release gates

The application has organization tenancy. Provider selection and credential overrides must therefore be organization scoped. Delegated self-host authentication supplies an implicit owner; hosted owners and admins manage integrations through the existing permission gate. An organization administrator cannot change installation environment variables.

All DataForSEO HTTP calls converge in `src/server/lib/dataforseo/core.ts`. Paid calls use `client.ts`, which reserves and settles Autumn credits in hosted mode. Preserve this billing boundary and its charged-task errors. Task collection is deliberately unmetered. Existing section parsers validate task status and Zod item schemas. Presentation services already depend on these section results; keep them behind a compatibility adapter during migration.

## Vendor evidence

Verified public documentation on 20 October 2026:

- [DataForSEO authentication](https://docs.dataforseo.com/v3/auth/): Basic login/password. Existing `DATAFORSEO_API_KEY` is explicitly base64 `login:password`, not a Bearer token.
- [Treg REST protocol](https://treg.to/llms.txt): REST calls use `X-Treg-Token` on `https://treg.to/call/<catalog-id>`. MCP Bearer authentication is a different interface. Calls relay upstream response bodies. Actual cost is `X-Treg-Cost-Micro`; vendor body cost is not the Treg charge. No automatic failover is allowed here.
- [Treg keyword volume contract](https://treg.to/catalog/endpoints/dataforseo.google.keywords.volume): POST `/call/dataforseo.google.keywords.volume`, upstream DataForSEO `/v3/keywords_data/google_ads/search_volume/live`. One task per request, up to 1,000 keywords, 2,000 requests/minute vendor limit. Example body: `[{"keywords":["coffee"],"location_code":2840,"language_code":"en"}]`. Native response semantics are documented in [DataForSEO volume](https://docs.dataforseo.com/v3/keywords_data/google_ads/search_volume/live/). Catalog price at discovery: USD 0.09 per call. Treg 402 insufficient balance is distinct from upstream task failure in HTTP 200. No pagination for this batch endpoint.

A test token was supplied on 20 October 2026 with an explicit free-checks-only limit. Free authenticated reads of `/auth/me`, team memberships and the team balance succeeded; a deliberately invalid token received HTTP 401. The actual application adapter also passed a live `/auth/me` probe. No `/call` request was made, no metered charge was incurred, and the token was held only in process memory. Account details and balances are not returned by the adapter. This proves account authentication only. No successful/error live SEO fixture or billing settlement is claimed; all SEO capabilities remain unverified and activation is refused.

The administrator's Treg test now makes one fixed-host, free `GET https://treg.to/auth/me` request using `X-Treg-Token`, a 15-second deadline, redirect rejection and no retries. It validates the team identity fields and returns only authenticated status and sanitized metadata. HTTP authentication, rate-limit, upstream, malformed-response and timeout errors remain distinct. The settings service records authentication success separately from operation readiness, so a valid token cannot enable an unverified operation. The endpoint is the same account read used by the [official CLI's whoami command](https://github.com/superdesigndev/treg/blob/main/src/treg/cli.py).

Further public catalog evidence identifies `dataforseo.x.serp-google-organic-live-advanced` for `/serp/google/organic/live/advanced` and `dataforseo.x.dataforseo-labs-google-keyword-overview-live` for `/dataforseo_labs/google/keyword_overview/live`. Both use POST with exactly one task in a JSON array; market/language and SERP device/depth stay explicit. Their catalog prices are estimates, not this application's verified settled charges. These proposed direct DataForSEO mappings preserve vendor identity and avoid Treg's routed fallback. They remain disabled pending authorized live contract and billing checks. Do not infer SEO endpoints from the Treg/AnyAPI names or add a generic URL proxy.

## Implemented boundary

`src/server/providers/` contains the registry, transport adapters, operation capability inventory, typed connection results, credential encryption, database resolver and execution scopes. The DataForSEO adapter wraps the existing transport and section parsers. Existing UI components and their data shapes remain compatible. Paid calls still reserve and settle credits in `dataforseo/client.ts`; task collection remains free. If saving an already billed submission's task reference fails, the charged error preserves the cost, and rank tracking avoids a second purchase for that chunk.

Hosted credit metering remains active for organization credential overrides. This change does not introduce a BYOK exemption from application credits.

App requests, metered consumers and MCP project authorization establish an organization scope. The resolver reads committed settings once per execution. Rank, AI visibility and Lighthouse-enabled audit workflows checkpoint configuration references without plaintext credentials; step callbacks re-enter that scope. Queued task references retain provider, operation, configuration ID and revision. Previously submitted tasks without a reference use the original installation DataForSEO credentials. Standalone, unscoped CLI section readers retain their existing environment-only behavior; they do not select an organization's overrides.

R2 cache keys created in a scoped execution include organization, provider, upstream, revision and contract version. Existing caches miss after this change. New keyword metrics, rank-tracker metric summaries, rank snapshots, Lighthouse results and AI observations reference an immutable relational source record containing organization, provider, upstream, operation, configuration/credential version, settings revision, contract version and collection timestamp. A replayed workflow records its pinned configuration rather than the current active selection. AI JSON/CSV exports include safe provenance fields through a project- and organization-scoped join. Historical rows and browser-supplied metrics remain explicitly unattributed; no provenance is backfilled by guessing.

Research cache payloads retain their original source reference. Browser saves insert metrics only when none exist, preserving trusted server-collected metrics and provenance. Research waits for metric write attempts before returning; persistence errors remain logged and best effort, preserving the existing cached-results behavior. User-authored reports and legacy queued work that predates configuration references still require a provenance review before a second provider can activate. Drain legacy tasks before that rollout; this implementation does not reconstruct their original database selection from current settings.

The normalized keyword-metrics boundary returns explicit market/language scope, USD CPC, competition on a 0-1 scale and monthly search-volume units. It preserves input indexes, duplicate keywords, omitted metrics and measured zeroes. Failed batches do not discard successful batches or retry paid submissions. Upstream revocation or removing an old encryption key makes work that still needs it fail explicitly. It never moves that work to another provider. Drain environment-backed jobs before rotating the installation's environment credentials.

To remove the organization override, preview the server environment, test that exact candidate and activate it. Inactive encrypted versions remain available to existing jobs. An application rollback retains the additive tables; do not run destructive down migrations.
