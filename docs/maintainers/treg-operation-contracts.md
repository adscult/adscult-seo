# Treg operation contracts

Checked 20 October 2026 against [the live provider catalog](https://treg.to/catalog/providers/dataforseo) and [the HTTP integration guide](https://treg.to/integrate.md).

The adapter relays the named DataForSEO endpoint through `https://treg.to/call/<catalog-id>` with `X-Treg-Token`. It preserves market, language, device, depth, pagination and native result types for the existing validated normalization boundary. It never chooses another vendor. Path placeholders are sent as catalog query parameters (`country` or `id`). POST bodies are JSON arrays containing exactly one task. The vendor limit is 2,000 requests/minute; connection tests remain separately rate limited in the settings service.

Treg's `X-Treg-Cost-Micro` is the charge authority; a missing header means the team's own credential was used without a Treg charge. A native DataForSEO `cost` is not the Treg charge. Idempotency keys protect transport retries; no automatic retries or cross-provider fallbacks are added. Treg-owned refusals are sanitized without returning account balances or top-up links.

## Local verification runner

`pnpm exec tsx scripts/verify-treg-provider.ts --budget=0 --output=.logs/provider-verification/treg-free-evidence.json` requires `TREG_TOKEN` in the server environment. It checks the free account endpoint and Liechtenstein's small location catalog, validates the native task envelope, writes public sample evidence, and does not change application settings. The live zero-budget run passed with 22 locations and a recorded charge of zero micro-USD.

A positive `--budget` opts into seven sequential paid probes: advanced SERP, keyword overview, related keywords, suggestions, ideas, domain overview and backlink summary. The cap is the remaining total, carried in `X-Treg-Route-Max-Cost`, and execution stops at the first failure. Review the normalized results and receipts before changing the corresponding `smokeVerified` flags in the route manifest. One passing endpoint does not verify sibling operations. The script never changes those flags or activates a candidate automatically.

`TREG_MAX_CALL_COST_USD` sets the application's ceiling for one request (default USD 1; zero refuses billed calls). It is not a cumulative account budget. The runner temporarily replaces it with the remaining authorized total. This integration uses direct catalog IDs, so it does not invoke routed tools or purchase fallback results.

Hosted resale remains disabled: it requires durable receipt storage and Treg-specific credit reservation estimates before customer billing can be enabled. Self-hosted operation uses the administrator's Treg account. The existing encryption, tenant scoping, revision checks and inactive-candidate workflow remain in place.

## Rank tracker upstream choice (20 October 2026)

Each tracker now stores `searchProvider` as a scalar column. New trackers default to AnyAPI when Treg is active; existing rows migrate to DataForSEO to preserve their source. Direct DataForSEO installations keep their native behavior. The source is included in workflow parameters, so editing a tracker does not reroute work already enqueued. Snapshots record the actual upstream vendor.

The tracker form offers AnyAPI and DataForSEO through Treg. AnyAPI uses `POST /call/anyapi.google.serp.organic`, with `query`, `gl`, `hl`, `autocorrect: true`, `limit: 10` and explicit page numbers. Documentation: https://treg.to/catalog/endpoints/anyapi.google.serp.organic and https://getanyapi.com/api/google/search. Country codes must be explicitly mapped; unsupported countries never default to the US. This integration currently supports country targeting and two-letter languages. City targeting remains a DataForSEO option. AnyAPI exposes no device selection, so its snapshots use a separate provider-managed device key, table column, chart series and export labels. They are never written into desktop/mobile history.

Native `output.found`, `output.data.results`, URLs, positions are validated. A successful search miss is distinguished from HTTP, quota, timeout and malformed-response failures. Ranks preserve the returned positions, including gaps. Sources have returned both page-relative positions (1..10) and absolute positions (11..20 on page 2); only page-relative positions receive the page offset. Numbered pages let AnyAPI select an available source for each page; the deprecated cursor is not sent. Failed or invalid pagination remains unchecked rather than manufacturing a not-ranking snapshot. There is no application fallback to DataForSEO. Other SEO operations still use their existing explicitly mapped routes.

Pagination stops when the target is found, the requested organic depth is covered, or the result set ends. It is bounded to `ceil(depth / 10)` purchases, with a USD 0.002 ceiling per page (or the lower operator ceiling). Cost estimates use those same ceilings, rather than native DataForSEO task pricing. One lookup has a five-minute deadline and its single-attempt workflow step allows six minutes. Treg scheduled ranks use the live adapter because its native queue is unavailable. Hosted Treg resale remains blocked.
